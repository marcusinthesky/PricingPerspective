# Pricing Perspective - research website

A MDX-first website for three papers and three research notes by Marcus Gawronsky and Chun-Sung Huang. The visual system is deliberately black and white, typographic, and organised around a constellation motif: separate mathematical objects connected by one geometric language.

## Stack

- Next.js 16 static export and React 19
- TypeScript 7
- Tailwind CSS 4 with source-owned shadcn/ui components and the pinned shadcn CLI
- Lucide React icons
- Bun 1.4 as package manager, script runner, and preview server
- Biome and Oxlint for fast formatting and linting
- Storybook 10 using the recommended Next.js + Vite framework
- Lighthouse CI with enforced performance, accessibility, best-practices, and SEO budgets
- Local MDX for the long-form site and paper copy
- WebM/MP4 video fallbacks and AVIF/WebP imagery

Direct `@next/mdx` is used instead of a documentation framework. Fumadocs was considered, but this site currently has the paper collection, a three-entry Blog collection, and no client-side search or documentation tree. Avoiding that extra runtime surface keeps the exported publication pages smaller. Fumadocs becomes a sensible migration when the collection grows into a searchable methods or replication portal.

## Start from the workspace root

```bash
cd src/typescript
bun ci
cd apps/portfolio
cp .env.example .env.local
# Edit NEXT_PUBLIC_SITE_URL in .env.local
bun run dev
```

From `src/typescript/`, `bun run dev`, `bun run build`, and `bun run ci` use
Turbo to run the corresponding task across all workspace packages.

Production static export:

```bash
bun run verify
bun run preview
```

## GitHub Pages deployment

Pushes to `main` run `.github/workflows/typescript.yml`. The workflow first runs the workspace
quality checks, then builds the export with the GitHub Pages base URL and project path, preserves
the `.nojekyll` marker, and deploys `out/` through the `github-pages` environment.

The build output is `out/` (ignored and regenerated by CI). Visual preview images and their QA reports live under `preview/`.

## Edit the copy

Long-form copy lives in MDX:

```text
src/content/home.mdx
src/content/authors.mdx
src/content/papers/*.mdx
```

Blog entries expose computed word counts and reading times, plus pre-rendered
computer-generated WebM readings. The audio generator keeps tables, figures, and
equations out of the spoken stream and reads their explicit captions instead:

```bash
# Run from this directory after `bun ci`.
bun scripts/generate-blog-audio.ts
```

The generator uses the exact workspace-pinned `gray-matter@4.0.3` and
`kokoro-js@1.2.1` dependencies, renders long notes as bounded sentence batches
through the Kokoro CPU model, and uses the shell's `ffmpeg` to encode Opus/WebM
files under `public/audio/`. Regenerate audio after changing a blog's prose or
captions.

Paper titles, dates, arXiv identifiers, outbound links, researcher profiles, keywords, and short card summaries are centralised in:

```text
src/content/data.ts
```

Blog posts are public by directory membership. Each `src/content/blog/*.mdx` file owns its
title, summary, dates, category, ordering number, and keywords in YAML frontmatter. The content
loader derives the slug from the filename and computes word count and reading time from the body.

## Sync the LeanBlueprint

The `/blueprint/` tab frames the generated Lean 4 companion while keeping its source of truth in
`src/lean/blueprint`. Regenerate the Lean-owned web output, then copy it into the static portfolio:

```bash
just lean::build          # after changing Lean declarations or namespaces
just lean::blueprint-web
bun run sync:blueprint
```

The copied `public/blueprint-doc/` directory is a derived static artifact. The current generated
document contains the four formal chapters described in `src/lean/blueprint/README.md`.

## Links requiring author confirmation

Canonical arXiv, Hugging Face, SSRN, and ResearchGate links are configured for all three papers. Researcher profiles use the supplied canonical ResearchGate, ORCID, LinkedIn, Twitter, GitHub, Hugging Face, and Google Scholar destinations. See `docs/LINKS_TO_VERIFY.md`.

## Performance and SEO

The site has no analytics, consent manager, external font request, third-party script, client-side search, or JavaScript constellation renderer. The constellation is inline SVG; layout dimensions are fixed; the video uses `preload="none"`; and the exported pages are static.

Structured data includes `WebSite`, `CollectionPage`, `ItemList`, `ScholarlyArticle`, `Person`, `VideoObject`, and `BreadcrumbList`. Scholarly citation meta tags, Open Graph/Twitter metadata, a sitemap, robots directives, BibTeX, CFF, `llms.txt`, descriptive captions, and a transcript are included.

The Lighthouse budget targets 95+ performance and 100 for accessibility, best practices, and SEO, with explicit FCP, LCP, CLS, and blocking-time limits. A perfect remote PageSpeed result cannot be guaranteed before the final domain, CDN headers, and third-party link behaviour are known; the project is designed to keep the static pages within these budgets. See `docs/PERFORMANCE.md`.

Exact dependency pins are listed in `docs/VERSIONS.md`. Delivery checks and the environment boundary are documented in `AUDIT_REPORT.md` and `BUILD_STATUS.md`.
